# UI 交付与原型一致性报告

## 验收基线

- 已批准原型：`ai-repo-radar-prototype-v2.html`
- 正式实现截图：`docs/assets/dashboard.png`
- 主视觉检查：1280 × 720 实际浏览器视口；完整页面内容可纵向滚动。
- 响应式检查：390 × 844 原生 iframe 视口，内部可用宽度 375px。

## 一致性台账

| 对照点 | 已批准原型 | 正式实现 | 结论 |
|---|---|---|---|
| 全局框架 | 78px 深色导航轨 + 顶部 Context Bar | 相同层级、比例、橙色选中线 | 一致 |
| 扫描模式 | 浅灰紧凑索引控制白色单详情画布 | 真实最多 8 项仍使用同一 list-detail 模式 | 一致，数据密度提高 |

## 首屏文案差异

有两处经过需求驱动的刻意变化：

1. 原型副标题是“在三条信号里，找到今天真正值得打开的项目。”；正式版改成“在多条信号里，找到今天真正值得打开的项目。”，因为正式日报最多 8 项。
2. 原型索引写“3 项目 / 仅 3 项通过质量门槛”；正式固定样例写“8 项目 / 兴趣 6 · 快速涨星 1 · 探索 1”，内容来自真实规则结果，不硬编码审核数据。

仓库摘要、增长数值、快速开始和同步状态均改为数据驱动，因此会随日报变化；信息层级与组件位置保持不变。

## 浏览器交互验收

- HTMX 切换 `nova-labs/agent-forge` → `vectorwave/rapid-infer` 后，详情和 URL 同步更新。
- 点击“收藏”后立即显示“已记录 · 从明天开始生效”，outbox 和待同步计数同时更新。
- 收藏页能读取刚才的项目并展示保存日期、推荐原因和 GitHub 链接。
- 历史页能读取当日日报和全部推荐行。
- 状态按钮能展开 GitHub、MiniMax 和反馈同步三个状态。
- 390px 视口 `scrollWidth == clientWidth == 375`，页面无横向溢出；项目索引保留设计内的横向选择带。

## 已知非视觉发布门槛

真实 MiniMax Secret 冒烟和连续 7 天定时运行无法在公开代码构建阶段代替仓库所有者执行，必须在私有 Actions 环境完成。它们不影响固定样例与 Dashboard 的视觉验收结论。
